# Timesheet Bot Phase 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** End-to-end weekly timesheet without AI or Slack buttons: collect Slack activity, allocate with the 45m rule, store in Postgres, approve and submit to Tempo from the CLI.

**Architecture:** DDD bounded contexts (timesheet, allocation, activity) on top of a shared kernel. Domain packages are pure Go; application handlers depend on ports; adapters live under each context's `infrastructure/`. `cmd/timesheet` is the composition root.

**Tech Stack:** Go 1.22, pgx v5, goose v3 (embedded), slack-go, cobra, yaml.v3, google/uuid, Docker + Postgres 17.

Later phases (separate plans): Phase 2 Slack approval bot + outbox relay + scheduler; Phase 3 Claude agent policy + skills; Phase 4 learning context.

Spec: `docs/superpowers/specs/2026-10-09-timesheet-bot-design.md`.

Deviations from spec, decided during planning:

- `WorkActivity` lives in the shared kernel (published language shared by Activity and Allocation), so no domain package imports another context's domain.
- No sqlc: queries are hand-written with pgx (few tables, avoids a code-gen tool).
- Postgres integration tests run against the compose database when `TEST_DATABASE_URL` is set, instead of testcontainers.

Commits: the repository owner commits; each task ends with a test checkpoint instead of a commit step.

### Task 2: Shared kernel

**Files:** `internal/shared/kernel/{week.go,workday.go,issuekey.go,duration.go,activity.go,clock.go,event.go}` + `_test.go` for each value object.

Types:

- `WeekID{Year, Week int}`; `ParseWeekID("2026-W41")`, `WeekOf(time.Time)`, `(WeekID).Days() []WorkDay` (Mon-Fri), `(WeekID).Prev()`, `String()`.
- `WorkDay` (date only); `NewWorkDay(time.Time) (WorkDay, error)` rejects Sat/Sun (`ErrWeekend`); `ParseWorkDay`, `String()`, `Time()`.
- `IssueKey`; `NewIssueKey(s)` validates `^[A-Z][A-Z0-9]+-\d+$`; `ExtractIssueKeys(text) []IssueKey` dedupes, order preserved.
- `Duration` (minutes); `NewDuration(min)` requires positive multiple of 15; `Minutes()`, `Seconds()`, `String()` like `1h30m`.
- `WorkActivity{Day WorkDay, ChannelID, ChannelName, Text, Permalink, ThreadTS string, IssueKeys []IssueKey}`.
- `Clock` interface + `SystemClock`.
- `DomainEvent` interface `{ EventName() string; AggregateID() string; OccurredAt() time.Time }`.

Tests (table-driven): week parsing round-trip, `WeekOf` across year boundary (2026-12-31 is 2026-W53), weekend rejection, key regex accept/reject, extraction dedupe, duration 0/10/15/450.

- [ ] Write tests, run `go test ./internal/shared/...` (FAIL), implement, run again (PASS).

### Task 3: Timesheet aggregate

**Files:** `internal/timesheet/domain/{status.go,entry.go,timesheet.go,events.go,errors.go,repository.go,timesheet_test.go}`.

- `Status`: `draft, awaiting_approval, approved, submitted, rejected`.
- `Entry{ID, IssueKey, IssueID int64, Day, Duration, Description, TempoWorklogID string, SubmitAttempts int, LastError string}`.
- `Timesheet` methods: `New(id, userAccountID, week, dailyCap, policy)`, `AddEntry(...) error`, `Propose() error`, `Approve() error`, `Reject(reason) error`, `PendingEntries() []Entry`, `MarkEntrySubmitted(entryID, tempoID) error` (moves to `submitted` when none pending), `MarkEntryFailed(entryID, err) error`, `DayTotal(day)`, `PullEvents() []kernel.DomainEvent`, `Rehydrate(...)` for repositories.
- Errors: `ErrNotDraft`, `ErrInvalidTransition`, `ErrDayOutsideWeek`, `ErrDayOverCap`, `ErrDuplicateEntry`, `ErrEmptyTimesheet`, `ErrEntryNotFound`.
- `Repository{ Get(ctx, userAccountID, week); Save(ctx, *Timesheet); Delete(ctx, id) }`, `ErrNotFound`, `ErrConcurrentModification`.

Tests: each invariant, every legal and illegal transition, events emitted per transition, submit completion.

- [ ] Tests first, then implementation, `go test ./internal/timesheet/domain/...` PASS.

### Task 4: Allocation domain + RulePolicy

**Files:** `internal/allocation/domain/{proposal.go,policy.go,rule.go,rule_test.go}`.

- `ProposedEntry{IssueKey, Day, Duration, Description}`, `Proposal{Policy string, Entries []ProposedEntry, Reasoning map[string]string}`.
- `Input{Week, Activities []kernel.WorkActivity, ChannelDefaults map[string]kernel.IssueKey, DailyCap kernel.Duration, PerKey kernel.Duration}`; `Policy interface{ Name() string; Allocate(ctx, Input) (Proposal, error) }`.
- `RulePolicy`: 45m per distinct key per day; keyless activity in a mapped channel goes to the default issue; days over cap scaled by `scaleDay` (owner-written, see Task 4b).

Tests (golden): two keys one day, same key twice one day = one entry, channel default, unmapped keyless ignored, over-cap day scaled and `<= cap`.

### Task 4b: `scaleDay` (repository owner)

`func scaleDay(entries []ProposedEntry, capMin int) []ProposedEntry` in `rule.go`. Contract: result total `<= capMin`, each entry a positive multiple of 15, entries never dropped below 15m.

### Task 5: Activity context + Slack collector

**Files:** `internal/activity/domain/source.go`, `internal/activity/infrastructure/slack/{collector.go,collector_test.go}`.

- `Source interface{ Collect(ctx, week) ([]kernel.WorkActivity, error) }`.
- Collector: `search.messages` with query `from:<@USERID> after:<Sunday> before:<Saturday>`, count 100, paginate all pages, convert `ts` to local day in configured timezone, skip weekend days, extract keys.
- Test against `httptest` server serving a two-page fixture.

### Task 6: Shared HTTP retry transport

**Files:** `internal/shared/httpx/{retry.go,retry_test.go}`.

- `RetryTransport{Base http.RoundTripper, MaxAttempts int, Sleep func(time.Duration)}` retries 429 and 5xx, honors `Retry-After` seconds, exponential backoff 1s,2s,4s..., rewinds bodies with `req.GetBody`.
- Tests: 429 then 200 (sleep called with Retry-After), gives up after max attempts, POST body resent intact.

### Task 7: Jira issue directory + Tempo gateway

**Files:** `internal/timesheet/application/ports.go`, `internal/timesheet/infrastructure/jira/{client.go,client_test.go}`, `internal/timesheet/infrastructure/tempo/{client.go,client_test.go}`.

- Ports: `IssueDirectory{ Resolve(ctx, key) (Issue, error) }` with `ErrIssueNotFound`; `WorklogGateway{ Create(ctx, Worklog) (string, error) }`; `Worklog{IssueID, Day, StartTime "15:04:05", Seconds, Description, AuthorAccountID}`.
- Jira: `GET {base}/rest/api/3/issue/{key}?fields=summary`, basic auth, 404 maps to `ErrIssueNotFound`, in-memory cache.
- Tempo: `POST {base}/worklogs` bearer auth, returns `tempoWorklogId` as string.
- Tests with `httptest`: auth header, request body, 404 mapping, id parsing.

### Task 8: Application handlers

**Files:** `internal/timesheet/application/{propose.go,approve.go,submit.go,handlers_test.go}`, `internal/timesheet/infrastructure/memory/repository.go`.

- `ProposeHandler{Repo, Source, Issues, Policies []Policy, Clock, UserAccountID, DailyCap, ChannelDefaults}.Handle(ctx, ProposeCommand{Week, Force, DryRun}) (*domain.Timesheet, error)`:
  existing and not forced: `ErrAlreadyProposed`; forced and submitted: error; collect, drop unresolvable keys, try policies in order, first proposal that builds a valid aggregate wins (validation errors recorded), `Propose()`, save unless dry run.
- `ApproveHandler`, `RejectHandler`: load, transition, save.
- `SubmitHandler`: load approved, iterate `PendingEntries()` sorted by day, start time 09:00 plus cumulative minutes per day, create worklog, mark submitted or failed, save after each entry (per-entry idempotency).
- In-memory repository for tests and dry runs.
- Tests: happy path, already proposed, force, policy fallback when first policy returns invalid proposal, submit partial failure then retry submits only remaining.

### Task 9: Postgres repository + migrations

**Files:** `migrations/{embed.go,00001_init.sql}`, `internal/timesheet/infrastructure/postgres/{repository.go,repository_test.go (integration tag)}`, `internal/platform/db/{db.go}`.

- Tables `timesheets`, `timesheet_entries`, `outbox` (spec section 11; learning tables come in Phase 4).
- `Save`: tx; insert when version 0 else `UPDATE ... WHERE id AND version`, 0 rows gives `ErrConcurrentModification`; replace entries; append pulled events to `outbox`.
- `db.Migrate(ctx, dsn)` runs goose with the embedded FS.
- Integration test: save, get round-trip, stale version conflict, outbox rows written.
