## Corrections

- **#13, Tempo error body.** The spec gives two shapes: the `ErrorBean` schema says `errors` is an array, and the prose and examples show `errors` as an object. Task 6.1 should decode both `errors[0].message` and `errors.message`, and fall back to an empty `Reason`. 401 and 403 are documented as `text/html`, so do not expect JSON on them.
- **#70, Dependabot for compose.** Use `package-ecosystem: docker-compose` for `/`. The repository already has this entry. WP-9 adds no `docker` entry for `/`; it keeps the existing `docker` entry for `/services/timesheet-core` and the `docker-compose` entry for `/`.
- **#71, distroless.** Switch to `gcr.io/distroless/static-debian13:nonroot`, then pin its digest. On 2026-10-09 this tag resolved to an OCI index. If the plan keeps `static-debian12`, the digest pin freezes a base image that no longer gets updates, and Dependabot has no newer `-debian12` build to move to.
- **#72, CI service image.** The docs list no Dependabot ecosystem that updates `services:` images in workflow files. Either refresh that digest by hand with `docker buildx imagetools inspect` (and add the step to `docs/commands/docker-and-runtime.md`), or leave the CI service on a tag.
- **#73, digest in `services.image`.** The docs neither confirm nor rule out a digest reference. Prove it with the first CI run after WP-9, before you rely on it.

## Notes for the plan (not verdicts)

- **Repository mismatch, section 0 row "Image digests".** The plan says `postgres:17 (compose)`. `docker-compose.yml` actually uses `postgres:17-alpine`, the same tag as CI. Task 9.1 resolves a digest for `postgres:17`, which nothing uses.
- **#45, `NOT VALID` and updates.** The check is enforced on updates too. Any later `UPDATE` of a legacy outbox row that leaves `user_account_id` NULL fails, for example a Phase 2 relay marking a row published. Add this to the Q2 risk.
- **#7, pagination.** `next` is optional and is a full URL. The plan's stop rule ("`metadata.next` is empty or a page is empty") fits the schema. `limit` has no documented maximum, so keep it at the default of 50.
- **`getWorklogsByUser` 404.** The spec documents "'404': description: User cannot be found in the system". Task 6.1 says a non-2xx from `ListByAuthor` "is classified as for `Create`", which would map this 404 to `ErrCreateRejected`. Decide whether a lookup error should use a create-specific sentinel.
- **#40, `RuntimeParams`.** Set the two keys on the existing map; do not assign a new map. Assigning a new map drops any parameters the DSN supplied, such as `application_name` or `search_path`. Keys you set in code override the same keys in the DSN.
- **RFC 9110 9.2.2 also says** "A client SHOULD NOT automatically retry a failed automatic retry." That sentence covers retries after a communication failure. The plan never retries transport errors, so it does not apply. Its 429 and 5xx retries rest on R3, not on this section.
- **Moved URL.** `https://api.slack.com/methods/search.messages` now redirects (`302`) to `https://docs.slack.dev/reference/methods/search.messages`. `slacksearch/testdata/SOURCES.md` (Task 2.2) should record the new URL.
- **Tempo doc anchors.** `https://apidocs.tempo.io/#tag/Worklogs/operation/<operationId>` is rendered by JavaScript, so the anchor page itself cannot be fetched as text. Its parts, tag `Worklogs` and operationIds `createWorklog`, `getWorklogsByUser` and `searchWorklogs`, exist in the spec.
